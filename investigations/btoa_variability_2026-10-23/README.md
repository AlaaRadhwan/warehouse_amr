# B → A navigation variability — root-cause investigation (2026-10-23)

Question: why does the B → A mission sometimes **succeed**, **spin indefinitely**, or **stall** — including with the calibrated
`wheel_separation_multiplier` (0.92754)? This directory is **instrumentation, data and analysis only**. Nothing under `src/`,
no Nav2/MPPI/planner parameter and no git state was changed. Nothing here is committed.

Predecessor documents: `calibration/nav_validation/reports/b_to_a_validation_report.md` (Oct 22) and
`Findings/Warehouse_AMR_BtoA_Behaviour_Variability_2026-10-23/` (Oct 23 behaviour report).

## Experimental design (what is held fixed)

* **Start condition:** robot spawned at Station B `(8.716, 2.705, yaw 0)`; AMCL initial pose set to the same. Goal: B→A staging pose `(0.099, -0.175, 0)`. Home → B → A is *not* mixed in.
* **Single difference between arms:** the `wheel_separation_multiplier` line. Both arms are generated by the same code from the current repo files; `runs/<id>/variant/variant.json` records the diff against the repo file (one line or none), and `runs/<id>/param_dump/` holds every node's parameters after launch so the arms can be compared mechanically.
* **No Nav2/MPPI parameter is touched.** MPPI `visualize: true` is the existing setting (provides `/optimal_trajectory`, `/transformed_global_plan`). `/trajectories` (≈1.9 MB/message) is deliberately not recorded; per-critic costs are not published by this MPPI build (1.3.12) — listed as missing measurements in the report.
* **Limits:** 120 sim-s after goal acceptance (observed successes take 40–60 sim-s) **and** a 330 s wall-clock safety limit (RTF ≈ 0.6 means the sim limit needs ≈ 200 s wall). The online watchdog may end a run early once a failure is established, after `POST_TRIGGER` more sim-seconds of evidence; this is recorded as `end_reason`.
* **Run order:** interleaved to spread slow drift in machine load over both arms. **Desktop load (browser, shell) was present** and is logged per run (`load_snapshot_*.txt`, `sysmon.csv`); it is a timing confounder that was not controlled.
* **Recorded in the bag (wall-clock log time; header stamps are sim time):** `/tf`, `/plan`, `/unsmoothed_plan`, `/transformed_global_plan`, `/optimal_trajectory`, the whole command chain (`/cmd_vel_nav` → `/cmd_vel_smoothed` → `/cmd_vel` → `/diff_drive_controller/cmd_vel_out`), raw and fused odometry, IMU, joint states, `/amcl_pose`, `/scan`, `/local_costmap/costmap`, footprint, collision monitor state, BT log, `/diagnostics`, `/rosout`, NavigateToPose / FollowPath / ComputePath action status and feedback.

## Reproduce

```bash
cd investigations/btoa_variability_2026-10-23
source /opt/ros/jazzy/setup.bash && source ../../install/setup.bash
# one run (id, multiplier); refuses to overwrite an existing run directory; needs >= 3 GB free on /home
scripts/run_experiment.sh p07_m1.0 1.0
# the pilot (6 runs, ~35 min)
scripts/pilot.sh
# per run
python3 scripts/classify.py runs/<id>
python3 scripts/extract.py  runs/<id>
python3 scripts/analyze_run.py runs/<id>
# all runs
python3 scripts/compare_runs.py
```

Environment overrides: `SIM_LIMIT`, `WALL_LIMIT`, `POST_TRIGGER`, `SETTLE_S`, `MIN_FREE_GB`.
Scripts shut the simulation down through `calibration/nav_validation/kill_sim.sh` (trap on exit) and finalize the bag with SIGTERM (SIGINT is ignored by background jobs of a non-interactive shell).

## Outcome classes (see `config/classification_criteria.yaml`)

`SUCCESS` (Nav2 SUCCEEDED) · `SPIN` (ground-truth |mean yaw rate| ≥ 0.8 rad/s over 15 s while speed ≤ 0.25 m/s; subtype terminal / far-field) · `STALL` (≤ 0.25 m net displacement and |yaw rate| ≤ 0.15 rad/s over 20 s while the goal is unmet) · `OTHER_FAILURE` · `INCONCLUSIVE`.
